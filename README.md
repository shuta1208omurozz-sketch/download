# FloatSaver v0.9-alpha

Android動画・GIFダウンローダーの不具合対策版。BraveからURL取得、画質選択、内蔵ブラウザ検出、保存履歴を備えた開発版です。

## 変更点（v0.9）

- **動画の直リンクを検出しやすく**：HEADリクエストを拒否する配信サーバーに、1バイトのRange GETでファイル情報を問い合わせるフォールバックを追加しました。レスポンス本文は読み取りません。対応できないサイトもあります。
- **動画・GIFのファイル名**：固定の `video.mp4` / `animation.gif` ではなく、URLから安全な元ファイル名を取り出します。取得できなければ既定名を使用。
- **ファイル破損・誤保存対策**：HTML/JSONの応答を動画として保存しない判定を追加。容量の進捗計算の桁あふれを防止。
- **Brave連携**：3分前のURLを誤って使う可能性を下げるため、取得情報の有効期限を45秒に短縮。画面移動でURLが読み取れなくなった場合、古い情報を破棄します。
- **操作性**：フローティング終了ボタンを画面上部へ移動。クリップボードの取得制限でアプリが落ちないように修正。
- **候補一覧**：内蔵ブラウザの古い動画候補を一定時間後に整理し、同じ通信履歴が候補を更新し続けるのを軽減。
- **品質検証**：XML・JavaScriptスキャナの静的テストに加えて、動画URL分類・広告判定などのKotlinユニットテストをGitHub Actionsで実行。

## 基本操作

1. Braveで動画ページを開き、フローティングの「↓」→「BraveのURLを取得して調べる」（初回はユーザー補助の許可）。
2. 解析結果から画質と保存形式を選んでダウンロード。
3. 動画が見つからない場合は「ページを再生して動画を探す」を使い、本編の再生後に候補を選択します。
4. 「フローティングを終了（↓も消す）」で停止します。

保存先：`Download/FloatSaver`。

サイト別の許可リストはありませんが、**再生できる動画が必ずダウンロードできるわけではありません**。DRM、Cookieや署名の必要な動画、Braveの内部通信、広告が本編に組み込まれた配信等は取得できない場合があります。広告判定は推定であり、自動ダウンロードはしません。

GitHub Actionsの「Build FloatSaver APK」からデバッグAPKを入手できます。実機テストは別途必要です。

## APKのファイル名とバージョンの確認

GitHubでのビルド後、**Artifacts**には `FloatSaver-v0.9-alpha-build番号-APK` のように表示されます。ダウンロードしたZIPを解凍すると、中のAPKも `FloatSaver-v0.9-alpha-build番号-debug.apk` という名前になっています。

- **v0.9-alpha**：アプリ本体に設定されているバージョン。今後のアップデート時には自動的に新しいバージョン名に変わります。
- **build番号**：同じバージョン内で複数回ビルドされたものを見分ける番号です。
- **debug**：テスト用APKであることを示します。

ファイル名の変更のみで、アプリID・保存先・既存の動画解析機能や利用権限は変わりません。


## ZIPなしインストール・同一署名で更新する

GitHubの **[FloatSaver 最新APK](https://github.com/shuta1208omurozz-sketch/download/releases/tag/latest-debug)** から `FloatSaver-v◯◯-build◯◯-debug.apk` を直接タップすると、ZIPを解凍せずにダウンロードできます（GitHubへのログイン状況やブラウザーにより確認画面が表示される場合があります）。ビルドのArtifactsは従来どおりZIP形式のままです。

新しいAPKは毎回同じ署名になるよう、暗号化した署名鍵 `signing/floatsaver-signing.p12.enc.b64` を使用します。秘密鍵を公開しないため、GitHubリポジトリの **Settings → Secrets and variables → Actions → New repository secret** に `FLOATSAVER_SIGNING_SECRET` を**一度だけ**登録してください。この値は公開リポジトリにコミットしないでください。未設定の場合、署名なしのAPKが公開されないよう自動ビルドは失敗します。

すでにインストールされているAPKが別の署名鍵で作成されている場合、**最初の一回はアンインストールが必要**です。この署名設定でインストールした後は、その後の更新版を原則として上書きできます。同じ署名鍵を使ってもAndroidのアプリ側でバージョンコードが小さくなると上書きできないため、今後は `versionCode` を増やして更新してください。署名鍵の復号文字列は紛失すると復元できないため、安全に保管してください。


## 軽量化・ZIPなしの直接インストール（v0.10以降）

v0.10ではAPKをarm64-v8a専用にし、利用しないCPUアーキテクチャのPython/FFmpegを除いてダウンロード容量を削減しています。Xiaomi 13Tなどの64-bit Androidスマートフォン用で、32-bit専用機やx86エミュレーターにはインストールできません。動画の解析・変換機能は削除していません。

最新版APKをZIPなしで取得する固定URL：
https://github.com/shuta1208omurozz-sketch/download/releases/download/latest-debug/FloatSaver-Android-arm64.apk

Releaseにはバージョン付き `FloatSaver-v0.10-alpha-build番号-arm64-debug.apk` も同時公開します（中身は同じです）。署名鍵を維持してアプリのバージョン番号を上げれば、以降は原則上書きインストールできます。

Android/Brave自身のダウンロード管理の不具合はアプリ側から直接修正できません。APK軽量化は改善策であり、Braveでの完了動作を保証するものではありません。


## v0.11: 小窓とBrave連携を改善

- フローティングボタンを56dpから40dpに縮小しました。
- ボタンを押したときは巨大な常駐オーバーレイではなく、**コンパクトな通常のFloatSaver画面**を表示します。ホームやタスク一覧では通常アプリと同じ扱いになり、タスク一覧に巨大な小窓が居座る問題を防ぎます。
- 表示領域を端末画面の約半分までに制限し、内容はスクロール可能です。背景をタップすると閉じるほか、上部の「↓終了」からフローティングボタンごと停止できます。
- 「BraveのURL / コピーを取得して調べる」は、URLを取得できない場合も勝手にユーザー補助の設定を開きません。代わりに、Braveで「共有 → FloatSaver」またはURLをコピーして利用するよう案内します。
- 自動的なBraveのURL取得には引き続きAndroidのユーザー補助権限が必要です。権限を与えていなければ、Braveの内部タブ情報をAndroidの制限を超えて取得することはできません。

※ 実機でのジェスチャーナビゲーションやタスク一覧の挙動はAndroid端末固有のため、APKビルド成功後も端末上での確認が必要です。


## v0.12: 複数ブラウザのURLと操作改善

- Brave・Chrome・Edge・FirefoxなどからURLを「共有 → FloatSaver」して解析できます。コピーも利用できます。
- 任意のユーザー補助権限により、Brave・Chrome・Edge・Firefox・Vivaldiのアドレス欄のURL自動取得を試みます。自動取得はブラウザの画面構造によって失敗する場合があります。通信は読み取りません。
- 「ブラウザのURLを取得して調べる」にボタンを統一。ユーザー補助の設定画面へ勝手に移動しません。
- 解析失敗時は同じ画面のステータス直下から「再生して動画を探す」へ進めます。
- 小型フローティングボタンは約1秒長押しで終了、短くタップすると従来どおり開きます。
- 画面上部に実際のインストール済みアプリのバージョンを表示します。

※ システムの制約により、ユーザー補助の許可なく別アプリのアドレス欄を直接読み取ることはできません。DRM保護や認証が必要な動画は保存できない場合があります。


## v0.13: URLが取得できない・同じURLが繰り返される問題

- 「制限付き設定を許可」はAndroidの制限を解除する設定で、ユーザー補助サービスそのもののオン状態とは異なります。ユーザー補助 → ダウンロードしたアプリで「FloatSaver：ブラウザのURL取得」をオンにする必要があります（任意）。
- 「ブラウザのURLを自動取得」は **ユーザー補助で最近検出したURLのみ** 使用。以前のクリップボードURLにはフォールバックしません。
- 「コピーURLを調べる」は、ユーザーが明示的にタップしたときだけクリップボードから取得。入力欄と同じURLなら再解析せず案内を表示します。
- 自動取得のURLは直近12秒間のみ有効。ブラウザの画面・タブ移動イベントでは以前のURLを無効化するよう強化。
- 画面に自動取得が「許可済み」か「未許可」か表示。ブラウザの画面構造によってはURLが取得できないため、その場合は共有機能を案内します。

※ブラウザのURLが取得できない状態から、ユーザー補助を許可するだけで必ず取得できるようになるとは限りません。Android端末やブラウザのUIによってアドレスバーを読めない場合があります。


## v0.14: 内蔵ブラウザの広告ブロックと戻る操作

- 内蔵ブラウザに **「広告ブロック：ON/OFF」** のスイッチを追加しました。初期設定はONで、変更は端末内に保存されます。
- ON時は広告配信に使われる一部の既知ドメインへの通信と遷移を遮断します。外部ブラウザ（Brave/Chromeなど）の広告設定には影響しません。広告ブロックサービスへの通信は行いません。
- 広告の別ウィンドウが新しく開く操作を抑制します。
- 一部のサイトは広告の読み込みが必要なため、動画が再生できない場合はOFFにしてページを再読み込みしてください。すべての広告やポップアップをブロックできるわけではありません。
- 広告ページへの移動によってWebViewの履歴が失われても、**「←戻る」や「元ページ」** で最初の動画ページに戻れるようにしました。端末の戻るボタンも同じ動作です。
- 動画候補を検出し保存する既存の仕組みは変更していません。

特定サイトでは広告ブロックのON/OFFで動画検出結果が異なる可能性があり、実機・実サイトでの確認が必要です。


## v0.15: 動画を取得できない場合の再点検

- 内蔵ブラウザでメディアとして見つかった**拡張子のない動画URL**も、動画のMIMEタイプが確認できれば元のファイルとして保存可能にしました。WebページのURL一般を勝手に動画扱いにはしません。
- HTMLの `data-video-src`/`data-media-url` や VideoObject の `contentUrl` が拡張子なしでも「動画候補」に表示されるよう改善しました。`data-hls-src`/`data-mpd-src` は「配信候補」として解析します。
- HTTPの途中切断や不完全な部分レスポンスを完成動画として保存しないようにし、通信エラーは1回自動で再試行します。
- GIFの進捗計算で大きいファイルが桁あふれする可能性を修正しました。
- ネットワーク側の署名期限切れ、ログイン制限、DRM保護による取得失敗はこの修正でも解消できないことがあります。


## v0.16: 内蔵ブラウザのまま保存、広告からの復帰を簡単に

- 内蔵ブラウザで検出した動画候補をタップすると**同じ画面上で画質候補を表示**。画質をタップしてそのまま保存を開始できます。ブラウザから毎回FloatSaverの別画面へ移動する必要はありません。詳細な容量・形式の指定をしたい場合だけ「詳細設定」を選べます。
- 選択した動画候補を解析できなかった場合にも、ブラウザの再生画面は残ります。別候補を試せます。
- 広告ブロックON時、最初に開いた動画ページから**別サイトへの予期しないトップレベル移動**を抑制します。動画ファイルや埋め込みフレームなどのサブリソース通信はこの規則で遮断しません。
- 手動で「埋め込みプレイヤーを開く」を選んだ場合には、そのプレイヤーのホストへの移動を許可します。広告ページへの追加リダイレクトは抑制します。
- 正当なログイン遷移や別サイトのプレイヤー移動まで止める場合があります。そのときは広告ブロックをOFFにしてください。
- 元の動画ページで戻る履歴がないときは、戻るボタンを1回押しただけで内蔵ブラウザを終了しないようにしました。もう一度押せば終了します。

※画質取得や保存は従来と同じ抽出方式であり、DRM・認証制限は解決しません。実機での広告・ページ遷移の動作検証は必要です。
