# FloatSaver v0.6-alpha（広告判定・保存安定性再点検版）

Android 10以上（targetSdk 35）の個人向け動画・GIF保存アプリのソースコードです。**APKではありません。Android SDKのない環境で改修したため、全体のビルドと実機検証は未実施**です。

## 使い方（3段階）

1. Braveの共有メニューからFloatSaverにURLを送るか、フローティングボタンを開いてURLを貼り付ける。ページ内の候補を探すなら「内蔵ブラウザで検出」からページを開き、広告が終わってから動画本編を再生する。
2. 「動画を調べる」で候補の再生時間・画質・**推定**容量を表示し、保存形式（元の形式・MP4・WebM・MKV）を選ぶ。GIFは元のGIF形式で保存する。
3. 「ダウンロードを開始」をタップする。結果は通知または「保存履歴」から確認する。保存先は `Download/FloatSaver`。

サイト別の許可リストやブロックリストは設けていません。外部の広告付きダウンロードサイトも使いません。

## v0.6で見直した点

- **広告判定の更新処理**：旧版は一度「広告の疑い」と判定されたURLが、その後に本編へ切り替わっても疑いが残り続ける場合がありました。動画要素を再観察し、広告マーカーが消えてから**実際の再生位置が3回連続で進んだ場合のみ**疑いを解除します。ネットワーク上のURLだけでは解除しません。
- **本編候補の誤認対策**：1回の再生検出だけで「本編候補」にしません。再生位置が進んでいることを2回以上確認し、再生時間情報と併せて「本編候補（未確認）」と表示します。候補を自動保存することはありません。
- **ページ移動時の古い結果**：古いページの `onPageFinished` によって現ページを上書きする可能性を減らしました。
- **履歴DBの不具合耐性**：履歴DBに書けない場合も実際のダウンロードは続け、成功・失敗を通知するよう変更しました（DB異常時は履歴が残らない場合があります）。
- **コード分割**：広告判定・再生証拠の扱いは `AdClassification.kt` に置き、ブラウザ・保存サービスから再利用する構造を維持しています。

**重要：サイトを限定していません。ただし広告と本編を100%区別することはできません。** 特に同じURLを広告と本編が共用する配信、広告と本編が結合された動画、DRM配信、別アプリ（Brave）の内部通信は判定・直接取得できない場合があります。短編動画を長さだけで広告扱いすることはありません。

## v0.5の変更（広告を本編と誤認しにくくする）

- **広告候補の区別**：内蔵ブラウザで、再生中の `<video>` 要素、再生経過時間、動画の長さ、プレーヤー周辺の広告表示を調べます。URLの `ads` / `preroll` / `midroll` なども補助的な手掛かりとして利用します（**サイト別のブロックリストはありません**）。
- **一覧の表示**：「本編の可能性（要確認）」「再生中（要確認）」「未判定」「広告の疑い」に分類します。本編らしい候補を上、広告の疑いがある候補を下に並べます。
- **保存ミスの抑制**：「広告の疑い」候補をタップすると確認ダイアログを表示します。広告も含めて誤って捨てないよう、候補は自動削除しません。保存操作はユーザーの確認が必要です。
- **広告終了後に更新**：再生状態を4秒おきに再評価し、広告が終わり本編が始まったら別候補として検出できる可能性を高めています。再生が止まった動画は一定時間後に優先度を下げます。
- **コードの分割**：広告の判定を `AdClassification.kt`、ページ内のメディア観察を `BrowserMediaScanner.kt` に分離。Kotlinソースは合計11ファイル。

**重要：広告と本編は100%判別できません。** サイト独自の広告再生器・同一URLへの広告差し込み・広告サーバーのURLに手掛かりがない場合は「未判定」や「再生中」となる場合があります。長い広告でも本編らしいと誤判定する可能性があります。短編・予告編など正規の動画を広告と誤認する場合もあります。判定はサイト制限・自動削除・強制スキップには使用しません。

## 以前のv0.4で見直した点

- **動画の選択**：同じ720pでもMP4とWebMで形式・サイズが異なる場合、両方の候補を表示。上位24件を表示します。容量が分からない候補も一覧から消さず、「容量不明」と明示します。容量フィルターは**目安**で、実際の上限は保証できません。
- **保存形式**：変換に失敗しても中間ファイルを誤って完成版として保存しないように、指定拡張子の出力が存在するかを検証します。
- **GIFと通信**：動画URLに不要なGIF確認通信（HEAD）をしないため、解析が遅れにくくなりました。GIFファイルはダウンロード後のファイル先頭で形式をチェックします。
- **検出精度**：内蔵ブラウザの裏側での通信候補が、ページ移動後に残る可能性を減らしました。SPA型のページ遷移も定期的に確認し、候補の一覧をリセットします。候補には広告動画が混じることがある旨を表示します。
- **動作負荷**：ページの自動再走査を4秒間隔に調整し、1回の走査の候補数を制限しました。
- **保存の安定性**：履歴DBのエラー時にキューが停止し続ける問題を回避。古い作業用ファイル（24時間以上前）を整理する処理を追加。Android 15のdataSyncフォアグラウンドサービスの制限時間に達した際は、yt-dlpプロセスを停止してサービスを終了する処理を追加しました。
- **画面**：履歴に「最新の状態に更新」を追加。Braveからの共有と内蔵ブラウザでの自動検出の役割を明示。画面上への重ね合わせ権限が取り消された場合にクラッシュしにくくしました。
- **共有からの解析**：URLを手入力で変更した場合、以前のページのReferer/User-Agentを使い続けないよう修正。

## 制限・未解決

- **Braveの内部通信を直接見られないため**、Brave上の動画をフローティングボタンが自動検出することはできません。Braveの共有／URL貼り付けと、内蔵ブラウザを使い分けます。
- `blob:`、DRM保護、ログイン・Cookie必須、署名付きURL、サイト独自の配信方法、拡張子がないメディア、動的プレーヤーなどでは検出・保存が失敗する場合があります。**全サイトで保存できることは保証できません。**
- 容量は既知サイズまたはビットレートからの推定であり、音声や変換後ファイルを含む正確な容量は事前にわからない場合があります。MP4・WebM・MKVへの変換には時間・空き容量・電池を消費します。
- 画質を高画質へ向上させる機能ではなく、配信元から取得できる形式の選択です。
- Android 15（API 35）では `dataSync` フォアグラウンドサービスは24時間につき通算6時間の制限があります。長時間の連続保存では中断され得ます。詳細：<https://developer.android.com/about/versions/15/behavior-changes-15>。
- ダウンロード履歴に元のURLをアプリ内SQLiteデータベースに保存します。署名・認証用のトークンをURLに含む場合は個人情報保護のため履歴を削除してください。ログや通知には元URLを表示しません。
- Google Play配信時はforegroundServiceの使用目的やサードパーティ依存物（FFmpeg / yt-dlp等）の利用条件・ライセンスを確認してください。

- Braveから共有→解析→保存、直接GIFの保存、内蔵WebViewで動画再生→候補表示をそれぞれ確認する。
